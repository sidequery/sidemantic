# BI converter comparison: Microsoft, ThoughtSpot, GoodData

Inspected source, fixtures and tests on 2026-11-06. Sidemantic HEAD `a7df3c9eae7c1a9a916ebe317ee378408d7d721b`; official Apache converters HEAD `011ea9f9a1e2c941f351e18e071622339ccae881`. Product code unchanged. This compares native Sidemantic adapters with the official converters; the Sidemantic canonical Ossie boundary is a separate layer, and a native parse/export round trip does **not** establish Ossie intermediary preservation.

## Microsoft Power BI / Fabric

**Directions/formats.** Both are bidirectional, but they do not have the same input contract. Sidemantic implements a native Python **TMDL** parser and emits a single TMDL script or split `definition/{database,model,tables,relationships}.tmdl`. It can take a directory containing `definition/`, or a file, but does not resolve a `.pbip` manifest or parse BIM/TMSL JSON. Official Microsoft accepts **BIM/TMSL mappings or JSON**, plus single-document TMDL and split TMDL/PBIP through optional Microsoft TOM/.NET. Plain BIM conversion requires neither TOM nor an online service. Sidemantic therefore has lower setup overhead for TMDL; official has broader Microsoft format coverage and the vendor object model for TMDL handling. Evidence: [Sidemantic source](/workspace/sidemantic/sidemantic/adapters/tmdl.py:152), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/tmdl.py#L152-L191); [official README](/workspace/ossie-converters-research/microsoft/README.md:108), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/microsoft/README.md#L108-L135).

**Import semantics.** Sidemantic maps tables/columns/measures/relationships into executable models; stores original DAX, expression language and passthrough syntax; reports unavailable optional `sidemantic_dax`, parse errors, and untranslatable measures. It translates a small native aggregate subset, with a particularly good `DISTINCTCOUNT` SQL compensation preserving BLANK-as-distinct and BLANK-on-empty semantics. Official defaults to DAX-tagged Ossie expressions with no SQL claim; opt-in `--translate-dax` handles exact supported aggregates, DIVIDE, arithmetic with BLANK rules, measure references and VAR/RETURN, preserving original DAX alongside SQL. Neither should be described as translating arbitrary DAX/context semantics. Evidence: [Sidemantic import](/workspace/sidemantic/sidemantic/adapters/tmdl.py:596), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/tmdl.py#L596-L645); [Sidemantic distinct-count compensation](/workspace/sidemantic/sidemantic/adapters/tmdl.py:1152), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/tmdl.py#L1152-L1160); [official translation scope](/workspace/ossie-converters-research/microsoft/README.md:422), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/microsoft/README.md#L422-L442).

**Preservation versus portability.** Sidemantic retains graph/model/column/metric TMDL properties, unknown child nodes, comments, raw names and DAX for same-adapter round trips. The loader explicitly merges `_tmdl_` graph attributes. Official has a versioned JSON `POWER_BI` custom-extension stash covering unknown properties, roles, partitions, hierarchies, perspectives, formatting, excluded tables and relationships. Official emits warnings for semantically unrepresented constructs, has CLI `--strict`, and separates structural TOM validation from opt-in real engine validation. Neither preserving roles in a blob nor retaining a TMDL role node means enforcing security in Sidemantic SQL or another Ossie consumer. Evidence: [Sidemantic passthrough](/workspace/sidemantic/sidemantic/adapters/tmdl.py:70), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/tmdl.py#L70-L149); [official loss policy](/workspace/ossie-converters-research/microsoft/README.md:251), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/microsoft/README.md#L251-L290).

**High-priority Sidemantic export defect, reproduced.** `_metric_to_dax` maps `count_distinct(customer_id)` to `DISTINCTCOUNT(Sales[customer_id])`, adding BLANK to the distinct count, and maps count(flag) to `COUNT(Sales[flag])`, which is unsuitable for boolean columns. Derived `metric.sql` is copied verbatim into DAX; probe `COALESCE(SUM(amount), 0)` remained unqualified SQL-shaped code. Official emits `DISTINCTCOUNTNOBLANK('Sales'[customer_id])` and `COUNTA('Sales'[flag])`, resolves physical versus model identifiers, and warns plus uses annotated BLANK placeholders when translation is unsupported. Fix export semantics and reject/report untranslatable SQL before adding format breadth. Evidence: [Sidemantic export](/workspace/sidemantic/sidemantic/adapters/tmdl.py:2277), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/tmdl.py#L2277-L2302); [official SQL-to-DAX rules](/workspace/ossie-converters-research/microsoft/src/ossie_microsoft/_sql_to_dax.py:25), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/microsoft/src/ossie_microsoft/_sql_to_dax.py#L25-L105).

## ThoughtSpot

**Directions/formats.** Sidemantic imports Table, legacy Worksheet, and modern Model TML. Each document becomes its own Sidemantic model; modern model joins can become derived SQL. Export emits only Table or Worksheet TML, including imported modern Models; it has no Model document emitter and no SQL View input branch. Official expects a set containing one modern Model plus its Table/SQL View documents, and emits the corresponding set. Its datasets represent participating Model table instances, so role-playing aliases are distinct datasets. It excludes predecessor Worksheets explicitly. Neither is a simple superset: Sidemantic covers legacy Worksheets and executable SQL, official covers modern document-set reconstruction. Evidence: [Sidemantic dispatch](/workspace/sidemantic/sidemantic/adapters/thoughtspot.py:662), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/thoughtspot.py#L662-L705); [Sidemantic export dispatch](/workspace/sidemantic/sidemantic/adapters/thoughtspot.py:1539), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/thoughtspot.py#L1539-L1574); [official mapping](/workspace/ossie-converters-research/thoughtspot/README.md:98), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/thoughtspot/README.md#L98-L110).

**Expression honesty.** Sidemantic rewrites bracket references into SQL and inlines nested formulas, but does not provide a complete ThoughtSpot-language translator or dialect preservation boundary in the native adapter. Official preserves formulas verbatim tagged THOUGHTSPOT and produces ANSI_SQL only for a resolvable bare column reference; reverse expression inventory exists but is explicitly not wired into import. Official export has an Ossie construct catalog (146 constructs, 108 native, 37 opaque warehouse SQL pass-through, one unsupported according to its README), structured issues and explicit fallback. Do not mistake catalog breadth for ThoughtSpot-to-SQL translation coverage. Evidence: [Sidemantic rewrites](/workspace/sidemantic/sidemantic/adapters/thoughtspot.py:121), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/thoughtspot.py#L121-L161); [official scope](/workspace/ossie-converters-research/thoughtspot/README.md:152), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/thoughtspot/README.md#L152-L209).

**Preservation/reliability gap, reproduced.** A Sidemantic table round trip discarded `connection` and `rls_rules`, and changed INT64 to DOUBLE with no adapter loss report. A SQL View document parsed to an empty graph. The native adapter constructs a selected semantic subset rather than stashing the full input. Official carries versioned THOUGHTSPOT vendor payloads, preserves foreign extensions, uses witnesses to avoid replaying stale metadata after edits, and emits structured ERROR for RLS loss. It deliberately drops GUID/obj_id/fqn and reports presentation/predecessor exclusions, so its broad README “lossless” language must be read with the coverage matrix. Priority: structured loss reporting and RLS failure, native Model+SQL View support, data-type/source metadata preservation, and bounded formula translation. Evidence: [Sidemantic field/model subset](/workspace/sidemantic/sidemantic/adapters/thoughtspot.py:763), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/thoughtspot.py#L763-L801); [type export](/workspace/sidemantic/sidemantic/adapters/thoughtspot.py:1593), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/thoughtspot.py#L1593-L1605); [official RLS error](/workspace/ossie-converters-research/thoughtspot/src/ossie_thoughtspot/tml_to_ossie.py:1982), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/thoughtspot/src/ossie_thoughtspot/tml_to_ossie.py#L1982-L2003); [official exceptions](/workspace/ossie-converters-research/thoughtspot/README.md:220), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/thoughtspot/README.md#L220-L227).

## GoodData

**Sidemantic is broader in native input shape.** It accepts Cloud LDM, legacy projectModel, wrapped/unwrapped data and SDK snake_case variants; SQL-backed datasets including object-form SQL; old flat sourceColumns and new references.sources; aggregatedFacts; date instances/dimensions. It exports Cloud LDM, carries labels/format/source metadata and unknown per-object extras, and re-emits workspaceDataFilterColumns as metadata. This is not an implementation of workspace security enforcement or MAQL analytical-model metrics. Official consumes a typed declarative `ldm` shape, rejects old sourceColumns, emits fields for facts rather than inventing aggregations, and explicitly does not convert metrics, aggregatedFacts or workspace filters. Its dataclass deserializer also has no SQL-backed-dataset field: a probe discarded SQL, aggregatedFacts and workspaceDataFilterColumns and emitted source `orders`, while Sidemantic retained SQL and both fact/aggregated-fact metrics. Evidence: [Sidemantic payloads](/workspace/sidemantic/sidemantic/adapters/gooddata.py:98), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/gooddata.py#L98-L172); [Sidemantic export](/workspace/sidemantic/sidemantic/adapters/gooddata.py:724), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/gooddata.py#L724-L744); [official deserializer](/workspace/ossie-converters-research/gooddata/src/ossie_gooddata/models.py:243), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/gooddata/src/ossie_gooddata/models.py#L243-L266); [official limitations](/workspace/ossie-converters-research/gooddata/README.md:101), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/gooddata/README.md#L101-L113).

**Semantic tradeoff and confirmed key defect.** Sidemantic turns numeric facts into default SUM metrics, which is useful for querying but an assumption absent from LDM. Official preserves facts as non-dimension fields with ANSI_SQL and MAQL references and does not imply an aggregate. Sidemantic sets primary_key to only `grain_ids[0]` and ignores explicit reference-source target IDs in query relationships, backfilling the target model's scalar primary key. Probe target grain [a,b], with sources ordered fk_b→b then fk_a→a, yielded foreign_key=[fk_b,fk_a], primary_key='a'. Official emitted exact ordered physical target columns [pk_b,pk_a]. Preserving full grain/source objects in metadata enables same-format reconstruction but does not repair execution semantics. Priority: honor full grain and each source.target mapping; make inferred aggregations explicit; preserve unknown/missing datatypes instead of asserting precision. Evidence: [Sidemantic grain](/workspace/sidemantic/sidemantic/adapters/gooddata.py:167), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/gooddata.py#L167-L168); [Sidemantic reference](/workspace/sidemantic/sidemantic/adapters/gooddata.py:405), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/gooddata.py#L405-L435); [Sidemantic backfill](/workspace/sidemantic/sidemantic/adapters/gooddata.py:918), [immutable](https://github.com/sidequery/sidemantic/blob/a7df3c9eae7c1a9a916ebe317ee378408d7d721b/sidemantic/adapters/gooddata.py#L918-L925); [official reference resolution](/workspace/ossie-converters-research/gooddata/src/ossie_gooddata/gooddata_to_ossie.py:223), [immutable](https://github.com/apache/ossie-converters/blob/011ea9f9a1e2c941f351e18e071622339ccae881/gooddata/src/ossie_gooddata/gooddata_to_ossie.py#L223-L264).

## Schema and test boundaries

Official converters emit one root model beside `version: 0.2.0.dev0`, not old semantic_model wrappers. Vendor data is JSON text under custom_extensions; dialect preservation is intentional. Current Sidemantic has a canonical schema-validated Ossie adapter; its `osi.py` opening module text describes legacy behavior, so do not use that docstring to claim current incompatibility. Native private `_tmdl_` attributes or `metadata.gooddata` are not automatically the same contract as official vendor payload schemas. Validate the actual full native→Ossie→native route separately.
